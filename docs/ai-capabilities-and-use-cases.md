# ERP AI: Verified Capabilities and Proposed Uses

Historical baseline before the AI workflow implementation. The requested workflows
and Gemini provider are now implemented locally; see [AI workflows](ai-workflows.md)
for current capabilities, limitations and deployment setup.

Code review dated 4 October 2026. This is an assessment of the checked-out code,
not a claim about which features are enabled on the production server.

## What Exists Today

The Coach module contains useful business intelligence, but most of the active
workflows are **deterministic rules and calculations, not generative AI**.

| Capability | Implementation found | Important qualification |
| --- | --- | --- |
| Coach dashboard and insight list | `app/web/coach.py`, `app/services/coach/coach_service.py` | Permission- and tenant-scoped views with severity, categories, and feedback |
| Finance alerts | `app/services/coach/analyzers/` | Cash-flow health, overdue receivables, upcoming payables, banking/reconciliation health, revenue trends, and expense approval issues |
| HR and operations insights | Same analyzer directory | Workforce turnover/staffing gaps, leave use/backlogs, inventory shortages/dead stock, workflow failures, fiscal-period health, and data quality |
| Weekly finance and HR digests | `app/services/coach/report_generator.py` | Aggregates recent insights into summaries and recommendations; current output explicitly uses no LLM |
| Scheduled insight/report generation | `app/tasks/coach.py`, analytics tasks | Requires configured workers/scheduling and current source data; tasks skip when Coach is disabled |
| LLM integration foundation | `app/services/coach/insight_engine.py` | Hosted Llama/DeepSeek configuration via a Chat Completions-compatible interface, model tiers, structured-output validation, caching, retries, and fallback |
| Context preparation | `app/services/coach/context_builder.py` | Helpers for anonymized entity codes and structured prompt context; not a guarantee that arbitrary input is automatically scrubbed |

`COACH_ENABLED` defaults to false in `app/config.py`. Coach permissions and module
availability are additional requirements. Provider endpoints, model names, and
credentials must be configured for model calls. I did not inspect production
secrets or verify production enablement.

Most importantly, application search found the `InsightEngine` implementation but
no invocation of that engine from the active Coach analyzers or report generator.
The reports set `model_used=None` and `tokens_used=0`. Enabling the flag or adding
an API key alone should not be described as turning on AI-generated advice;
the model-driven workflow still needs to be connected and tested.

No implemented general-purpose ERP chat assistant, AI CV screening workflow,
AI-generated job postings, or AI-written appraisals was identified in the inspected
application code. The Collaboration chat is employee messaging, not evidence of
an AI chatbot. The job pack produced in this task was generated by this coding
assistant, not by a newly installed in-app AI feature.

## Proposed Additions

These are product proposals, not features installed by this task. Effort is
relative implementation complexity, not a delivery-time commitment.

| Priority | Use case | User experience | Dependencies and controls | Relative effort |
| --- | --- | --- | --- | --- |
| 1 | Recruiting drafting assistant | Generate an editable job description, requirements, interview questions, and draft KRAs from an approved vacancy | Existing position/department context; human review; never publish automatically or invent pay/benefits | Medium |
| 1 | Grounded Coach explanations | Explain an existing alert and draft a weekly executive summary with links to the supporting metrics | Connect the existing LLM layer to safe aggregate context; preserve rule-based fallback; no autonomous finance actions | Low-medium |
| 2 | Marketing performance assistant | Summarize campaigns, explain changes in qualified leads/demos, and propose next experiments | Approved analytics/ad-platform imports and CRM attribution; show source period and freshness; budget changes require approval | Medium-high |
| 2 | KPI and appraisal assistant | Suggest measurable role-specific targets; summarize actual evidence; flag missing data before review | Fix KPI evidence saving first; add progress history and metric direction; manager sets final goals and ratings | Medium |
| 3 | Candidate evidence summaries | Summarize relevant experience and map cited portfolio/CV evidence to the agreed rubric | Restrict applicant data access; ignore protected characteristics and unsupported inferences; no automatic rejection or hiring decision | Medium |
| 3 | Policy and product knowledge assistant | Answer employee/product questions with citations to approved documents | Permission-filtered retrieval, tenant isolation, document versioning; explicitly say when evidence is absent | Medium-high |
| 3 | Support drafting and triage | Suggest a ticket category, identify possible duplicates, and draft an answer | Approved knowledge base; staff review before sending; no exposure of another customer's ticket | Medium |
| 4 | Document capture assistant | Extract invoice/receipt fields into a review queue and highlight discrepancies | Document storage/privacy controls, extraction validation, reconciliation, duplicate checks; approval before posting | High |

For Sherpackage, start with recruiting drafts plus grounded Coach explanations.
The first reuses the role/template work; the second builds on infrastructure
already present. Add the marketing assistant once reliable campaign-to-CRM
measurement is available, otherwise it will narrate incomplete data confidently.

## Shared Safeguards

- Enforce tenant and user permissions before gathering context, not only after
  generation. Model output must never decide which records a user may access.
- Minimize personal data sent to providers; define retention, logging, and vendor
  access policies before processing CVs or private employee records.
- Treat uploaded documents and retrieved text as untrusted content, not tool
  instructions. Validate outputs against schemas and allowlisted actions.
- Show supporting records, measurement windows, freshness, and uncertainty.
  Separate measured results from generated explanations and proposed actions.
- Require human approval for publication, messages, budgets, personnel decisions,
  accounting entries, and other consequential changes.
- Add usage limits that are actually enforced, request-level audit trails, failure
  handling, and a deterministic fallback. A configuration variable alone does not
  prove budget enforcement.
- Evaluate usefulness, factual grounding, permission leakage, and time saved on
  representative test cases before enabling a feature for all organizations.
